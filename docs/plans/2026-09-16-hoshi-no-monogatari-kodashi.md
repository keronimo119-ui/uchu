# 計画書: 星の物語を「かけら」で小出しに届ける仕組み（将来実装・設計のみ）

作成 2026-09-16。別セッションで Notion に執筆中の「星座の伝承」（2026-08-14時点 65件・12星座・1星座5〜6文化）を
アプリへ組み込むときの設計。**物語をずらりと並べず、少しずつ手に入るようにする**。読み手は「たくさん知った」と感じ、
毎回開く理由になる。実装は別セッション（監修方式・安いモデル）。本書は自己完結の設計書として書く。

## 1. 基本の考え方
- 単位は **「かけら」＝1段落（80〜140字）**。Notion 1ページ（1星座×1文化）が 6〜10かけら。
- かけらは **その星座の星をタップしたとき** に1つずつ手に入る（操作で進む。時間で勝手に進まない）。
- 読みたい人は「つづき」を押せばその場で次を読める（小出しでも、読みたい気持ちを止めない）。
- 1文化を読み終えると、次のタップで **「別の空から」** として次の文化の1かけら目が出る（Notion の相互リンク節と同じ発想）。
- 集めたかけらは **図鑑でいつでも読み返せる**。未入手は数だけ見せる（「残り 12」＝期待感）。
- かざす起動（別計画書）と結び、起動時に **「今夜のかけら」** ＝いま頭上にある星座の1かけら を1日1回出す。

## 2. データ形式 `stories.js`（オフライン同梱・stars.js と同じ読み込み方）
```js
window.UCHU_STORIES = {
  version: 1, generated: "2026-09-16",
  cons: {
    Sco: { name: "さそり座", cultures: [
      { id: "gr", name: "ギリシャ", title: "さそり座・ギリシャ — オリオンを刺した…",
        pieces: [
          { h: "空が語ること",        t: "本文1段落…" },
          { h: "伝えられてきた物語",  t: "本文1段落…" },
          { h: "伝えられてきた物語",  t: "補足…", sub: true },   // <details> の中身は sub
          { h: "独自の考察の見出し",  t: "…" },
          { h: "星のデータ",          t: "表を1行に要約した文（無ければ省く）" },
          { h: "余白",                t: "…" },
          { h: "問い",                t: "🧭マインド・コンパスの問い" },
          { h: "大切な言葉",          t: "最後のかけら（読み終えた印）" }
        ],
        source: "出典プロパティの文字列",
        links: ["cn","jp","me","ar","eg"]                        // 「別の空から」の相互リンク＝同星座の他文化id
      }
    ]}
  }
};
```
- 星座キーは `D.cons` の略符（Sco/Ori/…）。こぐま座等「対象星座=その他」のページはタイトルから判定する。
- 文化 id は固定表: gr=ギリシャ, cn=中国, jp=日本, me=メソポタミア, ar=アラビア, eg=エジプト, pl=ポリネシア,
  in=インド, na=北米, ro=ローマ, no=北方。Notion の `タグ` に無い文化はタイトル「◯座・エジプト — …」から取る。
- 本文中の `<span color="…">` は **色名だけ残して** `<em class="c-red">` 等に変換（人物・言葉の色分けを画面でも活かす）。
  その他のHTMLは落として素の文にする。他言語の語が紛れていないか（執筆側の失敗ログ参照）を変換時に警告する
  （ひらがな・カタカナ・漢字・英数字・記号以外の文字を検出したらページ名を出力）。

## 3. Notion → `stories.js` 変換ツール `tools/gen-stories.js`
- 入力: notion-fetch で取得した各ページの Markdown を `tools/notion-export/<略符>-<文化id>.md` として保存したもの
  （取得作業は Notion 連携が使えるセッションで行い、ファイルだけコミットする）。
- 規則: `## 見出し` で節を切る → 節内の空行区切りを1かけらにする → `<details>` 内は `sub:true` →
  `<table>` は1行要約に置き換えるか省く → 🎨色の凡例(callout)は捨てる → 🧭callout は「問い」「大切な言葉」の2かけらに →
  「## 別の空から」はリンク先の文化idだけ `links` に入れて本文は捨てる。
- 出力: `stories.js`（生成物・手編集禁止。stars.js と同じ扱い）。末尾に件数サマリ（星座数・文化数・かけら総数）を
  コメントで書き、README にも転記する。
- 1段落が 200字を超えたら句点で2つに割る。40字未満は前のかけらに連結（小出しの粒をそろえる）。

## 4. 小出しの規則（解放・順序・ペース）
- 進み具合 `localStorage 'uchu_pieces'`: `{ Sco: { ci: 0, pi: 3, done: false }, ... }`（ci=文化index, pi=次に出すかけらindex）。
- **解放トリガー**: `pickStar` で実在星カードを出したとき、その星の星座 `abbr` に物語があれば **次のかけらを1つ** 出す。
  同じ星座の星を何度タップしても1タップ1かけら。カード内の「つづき ▸」を押すと即・次のかけら（タップ不要）。
- **文化の順番**: 執筆順（配列順）。1文化のかけらを全部読むと `ci+1, pi=0`。次のタップで先頭に「別の空から ─ 中国では…」と
  小見出しを添える。全文化を読み終えたら `done:true`、以後はタップで **ランダムに1かけら再掲**（読み返しの楽しみ）。
- **ペース**: 1日の上限は設けない（操作した分だけ進む）。ただし **「今夜のかけら」は1日1回**（`uchu_pieces._today = 'YYYY-MM-DD'`）。
- **今夜のかけら**: 起動2.5秒後（今夜の見どころカードの後・そのカードが消えた直後）。観測地・恒星時（別計画書 §4.3 の
  `lstDeg`/`enuToEq` を共用）で **高度20°以上** にある星座のうち物語があるものから、進みが最も遅い星座を選び、次のかけらを出す。
  無ければ出さない。カードの小見出しは「今夜のかけら ─ いま頭の上の◯◯座」。
- 星座さがす（`selectCon`）のカードにも、進み具合「かけら 7 / 31 ─ ギリシャ・中国 を読了」を1行追加。

## 5. 画面
- 星カード（`#card`）の末尾に追加:
  ```html
  <div class="p">
    <div class="ph">✦ 星のかけら ─ ギリシャ 3/9 <span class="pn" id="pieceNext">つづき ▸</span></div>
    <div class="pb">本文（左寄せ・行間1.7・最大幅80vw）</div>
  </div>
  ```
  CSS: `#card .p { margin-top:9px; border-top:1px solid rgba(160,180,230,.25); padding-top:7px; }`
  `#card .ph { color:#9fb6e6; font-size:11.5px; letter-spacing:.08em; }` `#card .pb { color:#dfe6ff; font-size:13px; line-height:1.7; text-align:left; max-width:80vw; margin-top:4px; }`
  `#card .pn { float:right; color:#ffd9a0; padding:0 6px; }`
- **カードはタップで閉じる仕様**（`card.onpointerdown`）のため、`#pieceNext` は `pointerdown` で `stopPropagation()` して閉じさせない。
- かけら表示中はカードの自動消去を **8秒→20秒** に延ばす（読む時間）。`cardTimer` の設定箇所で切り替え。
- 図鑑（`#panel`）: 星座ボタンの右に小さく `7/31` を出す（物語がある星座のみ）。パネル上部に「集めたかけら ◯個」。
  星座ボタンの **長押し** で「読み返し」ビュー（入手済みかけらを文化ごとに全文表示・未入手は「残り n」）。
  読み返しビューは `#panelList` を差し替える形（新要素を増やさず、閉じるで元の一覧へ）。
- 文字の色分け `em.c-red` 等は控えめ（彩度低め・下線なし）。派手さより静けさ。

## 6. 検証フック（`window.__U`）
- `piece(abbr)` → 次のかけらを返して進める（本番と同じ処理）
- `pieceProg()` → 進み具合の全体（星座ごと ci/pi/done と合計）
- `pieceReset(abbr?)` → 進み具合を消す（省略で全部）
- `tonightPiece()` → 今夜のかけらの選定結果 `{abbr, altDeg, text}`（1日1回の制限は無視して計算だけ）
- `storiesStat()` → 星座数・文化数・かけら総数（stories.js のサマリと一致すること）

## 7. 実装ステップ（1ステップ＝1コミット・各ステップで検証）
1. `tools/gen-stories.js` と `tools/notion-export/`（まず 3星座ぶんで試す）→ `stories.js` 生成 → `storiesStat()` 一致。
2. 進み具合ストア + `piece(abbr)` ロジック（画面なし）→ フックで順序・文化切替・done・ランダム再掲を確認。
3. 星カードへの表示 + 「つづき」 + 自動消去20秒 → PC で `__U.testPick` 相当→カード確認。カードが閉じない/閉じるの両経路。
4. 今夜のかけら（起動2.5秒後・1日1回・高度20°）→ `tonightPiece()` と `setGeo` で緯度を変えて確認。
5. 図鑑の件数表示と読み返しビュー → 開閉・長押し・閉じるの経路を全部たどる。
6. 残りの星座を export → 再生成 → 実機で読みやすさ（文字量・行間・幅）を縦横両方の画像で確認。README/HANDOFF 更新。

## 8. 壊れうる箇所（先に洗う）
- `card.onpointerdown` で閉じる仕様と「つづき」ボタンの競合（stopPropagation を忘れると1文字も読めない）。
- カード幅 `width:fit-content` が長文で画面幅を超える → `.pb` に max-width 必須。横持ちは 60vw 程度に。
- `pickStar` は 8秒で閉じる `cardTimer` を上書きしている → かけら有無で秒数を切り替える1か所にまとめる。
- `selectCon` の視線移動中にカードを出し直す処理は無い（従来どおり）。かけらは星タップ側だけに足す。
- `localStorage` が使えない環境（プライベートモード）→ try/catch で無視し、その回だけ進み具合はメモリ上。
- 文字化け: `stories.js` は BOM 無し UTF-8。生成ツールで `fs.writeFileSync(..., 'utf8')`。

## 9. 執筆側（Notion セッション）へのお願い
- 段落は 80〜140字を目安に切る（そのまま1かけらになる）。1文化 6〜10段落。
- 「別の空から」節はリンクだけにし本文を書かない（変換で捨てるため）。
- `## 見出し` の書式（HANDOFF §4 の固定書式）を崩さない。変換ツールは見出し名で節を判定する。
- 他言語の語の混入チェックは変換ツールでも行うが、執筆時の目視確認は継続。
