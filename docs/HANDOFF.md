## 失敗した方法・試行ログ（同じ穴に落ちないこと）
- **歴史モードの惑星スプライトは作成時(0,0,0)=地球と同位置**。histFreezeを入った直後に有効化すると
  位置計算が一度も走らず巨大な光が画面を覆い「背景が真っ白」になる→ 作成直後に updatePlanets(0) を
  呼ぶ恒久修正済み(2026-07-08)。全面白＝「原点に取り残された発光スプライト」をまず疑う。
- **tourのフリックはドラッグ回転も兼ねる**(pointermoveで回した後にpointerupで切替判定)ため、
  1フリックでカメラが約200°回り、到着時に夜側(真っ暗)を向く事故→ 飛行中に定番構図(tTh=2.4,tPh=1.35)へ
  イージングで戻す方式で解決。到着直後が暗い時はこれを疑う。
- **プレビューサーバー(uchu-app)はセッション中に何度も勝手に落ちる**。スマホがERR_EMPTY_RESPONSEなら
  まず preview_list で生死確認→再起動。serve.ps1のKeepAlive問題(修正済み)と混同しないこと。
- 実機のボタン座標(1080x2520): 🪐惑星ボタン≈(953,1652)。フリック=input swipe 250 1100 850 1100 120。
- **カメラ用の変数名 `pos`/`vel` は星座標のFloat32Array `pos` と衝突**→モジュール全体が構文エラーで無起動
  （エラー表示なし・`__uchuStarted`もfalseのまま）。カメラ系は `cpos`/`cvel` を使うこと。
  原因調査は `node -e` でscriptタグ中身を `new Function()` に通す構文チェックが最速だった。
- **画面右方向は `cross(viewTarget, camUp)` の順**。逆順(camUp, viewTarget)だと左右が鏡写しになる(実証済み)。
- 遊泳カメラの失敗設計3代: ①方位角+lookAt=極で縦移動制限 ②剛体フレーム大円回転=回るだけで奥行きなし
  ③中心方向ダイブ=中心注視のままだと「後退・旋回」に見える。→ 最終法則(進行方向を見る+明示回頭)で解決。
- 視線を「最短経路で中心へlerp」すると回頭方向がフリックと無関係になり「毎回同じ方向に回る」と感じられる
  → steerAxis(フリック方向で決まる軸)周りの明示回転にすること。
- **serve.ps1 は KeepAlive のままだと adb reverse 経由で ERR_EMPTY_RESPONSE**(スマホだけ読めない)。
  接続ごとに閉じる+エラー時Abort に修正済み(2026-07-05)。スマホが古い版のままの事故はまずこれを疑う。
- adbデーモン再起動直後は `device not found` になる→数秒待って再試行で復帰する(USB再挿入は不要だった)。
- スマホのスクショは撮影前に `dumpsys window | grep mCurrentFocus` でChromeが前面か確認する
  (通知でLINE等が前面になっていると他人の画面を撮ってしまう事故が実際に起きた)。
- **BHの質量を成長させる設計は2度失敗**（全星呑み込み崩壊 or 完全凍結の双安定）。質量900固定+「満員時は最古の星が決定論的な死の螺旋で還る」設計で90分安定を確認済み。変更するなら `__U.advanceSim(5400)` 長期テスト必須。
- **このPCは `adb pair` が protocol fault で全滅**（adb 37/34、PowerShell/Bash、IP/mDNS名すべて）。回避: USBで一度「許可」→以後は無線も自動接続。
- プレビュータブが非表示だと rAF が1〜2fpsに制限される → 実時間待ちの検証は無効。フックで状態を進める。
- スクリーンショットは3〜10秒遅れる → 歴史モード終端(p>0.95)などは撮影前に一周してしまう。余裕のある時点にジャンプして撮る。
- 星が暗すぎ問題は「等級→輝度カーブ」調整で解決済み（vInt式）。安易に露出を上げず既存カーブを尊重。
